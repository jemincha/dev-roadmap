# 누가 제일 허슬했나

아티스트의 앨범 발매 기록을 **GitHub Contribution Graph와 유사한 형태로 시각화**하여, 어떤 아티스트가 얼마나 꾸준하게 음악을 발매해왔는지 살펴보는 웹 애플리케이션이다.

Spotify API 발급 및 사용 과정의 복잡성 때문에 현재는 **MusicBrainz API**를 중심으로 구현했다.

---

## 1. 프로젝트 목적

단순히 음악 정보를 검색하는 것을 넘어, 외부 API에서 가져온 데이터를 가공하고 시각화하는 것을 목표로 한다.

핵심 아이디어는 다음과 같다.

> **"누가 제일 허슬했나?"**

아티스트의 데뷔 이후 현재까지의 앨범 및 EP 발매 기록을 분기 단위로 나누고, 각 분기의 발매량을 GitHub Contribution Graph와 유사한 색상 단계로 표현한다.

사용자는 한 아티스트의 활동 기록을 확인할 수 있으며, 여러 아티스트를 추가하여 동일한 시간축 위에서 비교할 수 있다.

---

# 2. 현재 구현된 기능

## 2.1 아티스트 검색

검색창에 아티스트 이름을 입력하면 MusicBrainz API를 통해 검색 결과를 가져온다.

검색 결과는 드롭다운 형태로 표시되며, 원하는 아티스트를 선택하여 그래프에 추가할 수 있다.

### 현재 흐름

```text
검색어 입력
    ↓
MusicBrainz Artist Search
    ↓
검색 결과 표시
    ↓
아티스트 선택
    ↓
해당 아티스트의 발매 데이터 요청
```

---

## 2.2 앨범 / EP 발매 데이터 수집

선택된 아티스트에 대해 MusicBrainz의 Release Group 데이터를 요청한다.

현재 대상은 다음과 같다.

* Album
* EP

수집한 발매일을 기준으로 각각의 앨범을 연도와 분기로 분류한다.

---

## 2.3 Contribution Graph

아티스트의 데뷔 연도부터 현재까지의 기간을 기준으로 분기별 발매량을 계산한다.

각 분기는 다음과 같이 표현된다.

```text
0장   → 발매 없음
1장   → 낮은 활동량
2장   → 중간 활동량
3장+  → 높은 활동량
```

발매량에 따라 Contribution의 색상 단계가 달라진다.

GitHub Contribution Graph와 유사한 방식으로 한눈에 활동 패턴을 파악할 수 있도록 구성했다.

---

## 2.4 아티스트별 시작 연도 처리

아티스트마다 데뷔 연도가 다르기 때문에 그래프의 시작점도 각각 다르다.

여러 아티스트를 비교할 경우에는 **가장 먼저 데뷔한 아티스트를 기준으로 전체 그래프의 시간축을 설정**하고, 이후 데뷔한 아티스트의 데뷔 이전 구간은 실제 활동 데이터가 없는 구간으로 처리한다.

예:

```text
Artist A — 2000년 데뷔
Artist B — 2010년 데뷔

전체 시간축
2000 ───────────────────── 2026

Artist A
████░░███░████░░██████████

Artist B
──────────████░░██░██████
          ↑
       2010년 데뷔
```

이를 통해 데뷔 시점이 다른 아티스트도 동일한 시간축에서 비교할 수 있다.

---

## 2.5 분기 선택 및 앨범 정보 표시

Contribution Graph의 특정 분기를 클릭하면 해당 분기에 발매된 앨범 정보를 확인할 수 있다.

앨범 정보는 그래프 오른쪽의 상세 정보 영역에 표시된다.

다른 분기를 클릭하면 선택된 분기의 정보로 변경된다.

다음과 같은 방식으로 상세 영역을 닫을 수도 있다.

* 동일한 분기 다시 클릭
* 그래프의 빈 영역 클릭
* 닫기 버튼 클릭

---

## 2.6 다중 아티스트 비교

여러 아티스트를 추가할 수 있다.

아티스트가 추가되면 각각의 Contribution Graph가 세로 방향으로 배치되어 동일한 시간축에서 비교할 수 있다.

또한 각 아티스트를 제거할 수 있는 기능도 구현되어 있다.

현재 단계에서는 그래프 자체를 제공하고 **실제 비교 및 판단은 사용자가 직접 수행하는 방식**이다.

---

## 2.7 API 오류 처리

외부 API를 사용하기 때문에 다음과 같은 상황을 구분하여 처리한다.

### 검색 결과가 없는 경우

검색 요청 자체는 정상적으로 수행되었으나 검색 결과가 없는 경우.

```text
검색 결과가 없습니다.
```

### API 요청에 실패한 경우

네트워크 오류 또는 API 응답 오류 등으로 데이터를 정상적으로 가져오지 못한 경우.

```text
아티스트 정보를 가져오지 못했습니다.
```

이를 위해 API 요청 과정에서 발생하는 오류를 별도로 처리한다.

```text
HTML
 └─ 페이지 구조 및 UI

 └─ Contribution Graph 및 카드 UI
 └─ 반응형 레이아웃

 └─ 사용자 입력 처리
```

이는 Phase 5의 학습 목표에 맞춰 외부 데이터를 직접 가져오고 가공하여 화면에 표현하는 과정을 경험하기 위한 것이다.

# 4. 현재 데이터 구조

MusicBrainz에서 가져온 Release Group 데이터를 기반으로 아티스트의 발매 기록을 가공한다.

기본적인 처리 과정은 다음과 같다.

```text
MusicBrainz API
      ↓
Release Group 데이터
      ↓
Album / EP 필터링
      ↓
발매일 추출
      ↓
연도 / 분기 계산
      ↓
분기별 발매량 집계
      ↓
Contribution Level 계산
      ↓
Graph 렌더링
```

# 5. 현재 단계에서 보류된 기능

현재는 Contribution Graph를 **시각화하는 것까지** 구현되어 있다.

즉,

> "누가 더 열심히 활동했는가?"

를 사용자가 그래프를 보고 직접 판단한다.

자동으로 점수를 계산하여 순위를 매기는 기능은 아직 구현하지 않았다.

---

# 6. 향후 개발 방향

## 6.1 Activity Analysis

현재 Contribution 데이터를 활용하여 아티스트의 활동 패턴을 수치화할 예정이다.

초기 구상은 다음과 같다.

```text
Output
 └─ 발매 밀도

Quality
 └─ 앨범 평점

Hustle Score
 └─ Output + Consistency + Quality 등을 종합
```

단, 최종 알고리즘은 아직 확정하지 않았다.

실제 아티스트 데이터를 분석한 뒤 지표 간 관계와 분포를 확인하고 알고리즘을 설계할 예정이다.

---

## 6.2 Output

단순히 전체 앨범 개수만 비교하는 방식이 아니라 **활동 기간 대비 발매 밀도**를 기본 지표로 고려한다.

예:

```text
발매 앨범 수
──────────────
활동 기간
```

이를 통해 활동 기간이 긴 아티스트가 단순히 더 많은 앨범을 냈다는 이유만으로 유리해지는 문제를 줄이는 것을 목표로 한다.

---

## 6.3 Consistency

활동 기간 동안 실제로 앨범을 발매한 분기의 비율을 이용하여 꾸준함을 측정한다.

개념적으로:

```text
앨범을 발매한 분기 수
────────────────────
데뷔 이후 전체 분기 수
```

활동량과 꾸준함을 별개의 지표로 유지하는 것을 기본 방향으로 한다.

---

## 6.4 Quality

MusicBrainz에서 제공하는 커뮤니티 평점을 활용하여 앨범의 평균적인 평가를 별도 지표로 표시하는 방안을 검토하고 있다.

평점은 Output에 직접 합산하지 않고 **Quality라는 별도의 축으로 분리**하는 방향을 채택했다.

따라서 향후에는 다음과 같은 형태의 활동 프로필을 구성할 수 있다.

```text
Output       ████████░░
Consistency  ██████░░░░
Quality      █████████░
```

---

# 7. 보류된 데이터 확장

## Track Count / Running Time

앨범의 단순 개수뿐 아니라 다음과 같은 데이터를 활용하는 방안도 검토했다.

* 총 트랙 수
* 총 러닝타임

그러나 MusicBrainz의 Release Group 데이터만으로는 해당 정보를 직접 얻을 수 없다.

실제 트랙 정보는 개별 Release 및 Recording 데이터에 연결되어 있기 때문에, 앨범마다 추가 API 요청이 필요한 **N+1 요청 문제**가 발생한다.

현재 프로젝트의 규모와 MusicBrainz API rate limit을 고려하여 이 기능은 보류한다.

향후에는 다음과 같은 별도의 데이터 소스를 활용할 가능성을 열어둔다.

* Spotify API
* 다른 음악 데이터 API
* 별도의 데이터 수집 계층

# 8. 향후 확장 아이디어

현재 기능을 기반으로 다음과 같은 확장이 가능하다.

### 기간 필터

```text

```

등의 기간을 선택할 수 있도록 확장한다.

```text

Quality

```

등의 지표를 비교한다.

### 활동 프로필

단순 순위 대신 아티스트별 활동 특성을 보여준다.

예:

```text
높은 Output
낮은 Consistency
높은 Quality
```

또는

```text
낮은 Output
높은 Consistency
높은 Quality
```

처럼 서로 다른 활동 패턴을 비교할 수 있도록 한다.

# 9. 프로젝트의 학습 목표

이 프로젝트는 단순히 완성된 웹 서비스를 만드는 것이 목적이 아니다.

앞선 프로젝트에서 학습한 JavaScript와 Web API 활용을 기반으로 한 단계 더 나아가 다음 과정을 경험하는 것이 핵심이다.

```text
API 호출
   ↓
외부 데이터 이해
   ↓
데이터 필터링
   ↓
데이터 구조 변환
   ↓
데이터 집계
   ↓
시각화
   ↓
사용자 인터랙션
   ↓
데이터 분석
```

따라서 이후 기능을 추가할 때도 새로운 프레임워크를 무작정 도입하기보다는 **현재 기술 범위 안에서 데이터 가공과 분석의 복잡도를 조금씩 높이는 것**을 우선한다.

# 11. 현재 결론

현재 버전의 핵심은 **"아티스트의 활동량을 판단해주는 서비스"가 아니라 "판단할 수 있는 데이터를 시각적으로 보여주는 서비스"**다.

따라서 다음 단계에서는 기존 데이터를 기반으로 어떤 지표가 실제로 의미 있는지를 먼저 확인한 뒤, 그 결과를 바탕으로 분석 기능을 추가한다.

최종적인 목표는 단순한 Contribution Graph가 아니라,

> **아티스트의 발매 패턴을 데이터로 관찰하고 비교할 수 있는 서비스**

로 발전시키는 것이다.
